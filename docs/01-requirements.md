# 요구사항

## 문제
결혼 준비는 일정·체크리스트·비용·업체·하객 등 관리 항목이 많고, 정보가 블로그·카톡·엑셀·메모
등 여러 곳에 흩어져 **"무엇을, 언제, 얼마에"** 준비해야 할지 막막하다. 웨딩플래너 없이 커플이
스스로 준비하면 ① 항목 누락 ② 준비 순서 혼란 ③ 예산 초과·중복 지출 ④ 두 사람이 같은 정보를
실시간으로 공유하기 어려움 이 반복해서 발생한다.

## 사용자 · 이해관계자
| 역할 | 이 시스템으로 무엇을 하나 |
|---|---|
| 신부(나) | 전체 준비 현황 파악, 체크리스트·비용·일정·업체·하객 관리, 공유 코드 발급 |
| 신랑(애인) | 공유된 같은 데이터를 조회·기록, 담당 지정된 항목 확인 |

> 두 사람은 동등한 권한으로 **같은 공용 데이터**를 쓴다. 외부 사용자는 없다.

## 성공 기준
- [ ] 결혼 준비 전 과정의 할 일을 한 곳에서 확인하고, 표준 체크리스트로 **누락 항목을 0으로** 만든다
- [ ] 나·애인 **두 기기에서 공유 코드로 같은 데이터**를 조회·수정할 수 있다
- [ ] **예산 대비 실지출**과 **나/애인/양가 분담 정산**을 언제든 숫자로 확인할 수 있다
- [ ] 결혼 날짜를 입력하면 **D-day와 역산 로드맵**이 자동 표시된다
- [ ] 하객 명단을 **엑셀로 가져오고 내보낼 수 있다**
- [ ] (성능 목표의 수치 예산은 `02` 「성능 예산」에 둔다)

## 범위 (In Scope)
- **홈(대시보드)**: D-day, 체크리스트 진행률, 예산 소진율, 다가오는 일정/다음 할 일, 영역별 진행률,
  이번 달 **미니 캘린더 위젯**(일정·마일스톤·납부일 점 표시)
- **일정**: **월간 캘린더(날짜 셀에 일정·마일스톤·업체 납부일 표시) + 리스트(아젠다) 뷰 전환**,
  일정 등록(제목·날짜/시간·장소·영역태그·담당자·알림), 결혼일 역산 로드맵(표준 단계 시드),
  날짜 미정 모드, **길일(吉日) 표시 옵션**(만세력 기반 길일을 날짜 셀에 표식 — 날짜 선택 참고용),
  업체 계약일·예약금/잔금 납부일 자동 표시
- **체크리스트**: 한국 결혼준비 표준 시드 제공, 담당자 단순 표기, 영역별 진행률·필터
- **비용**: **지출의 단일 진실(원장)** — 예산 vs 실지출, 영역별 배분, 분담(나/애인/양가). 지출은
  업체별로 묶이고, 각 업체는 **기본 견적 + 추가 옵션 → 최종금액**(옵션 추가 시 최종금액 변동)으로
  관리한다. 영역 합계·전체 합계로 집계. 금액·옵션·최종금액 관리는 모두 비용 소관 (→ ADR-0001)
- **업체 관리**: **정보 관리** — 후보 비교(견적 참고), 계약 상태(후보/계약)·계약일·위치·역할
  (스드메 하위: 스튜디오/드레스/메이크업), 연락 메모. 한 영역에 여러 업체 계약 가능. 금액의 소스가
  아니며(상세는 비용), 계약·납부 **일정**은 일정 화면과 연동 (→ ADR-0001)
- **하객 관리**: 명단·축의금 장부·식대 계산 + 엑셀 업로드/다운로드
- **갤러리**: 준비 사진 + 결혼영상 등 다른 용도용 사진 원본 보관·분류
- **준비 영역 모아보기**: 영역별로 할일·예산·업체·일정·사진을 한 화면에 모은 필터 뷰
- **설정**: 결혼 정보, 공유 코드/링크, 백업/내보내기, 표준 시드 불러오기

## 범위 밖 (Non-goals)
**이 절이 스코프 크립을 막는다.** "안 하기로 한 것"과 "아직 안 한 것"을 구분해 쓴다.
- 회원가입·로그인·다중 사용자 계정 — 이유: 나+애인 전용, 외부 배포 없음 (안 하기로 함)
- 상용 서비스화·결제·구독 — 이유: 개인 실사용 목적 (안 하기로 함)
- 전국 웨딩홀/업체 DB 기본 제공 — 이유: 사용자가 직접 후보를 입력. 참고 제품의 956개 웨딩홀
  DB는 복제 대상이 아님 (안 하기로 함)
- 웨딩플래너식 업체 계약 대행 — 이유: 정보 관리 도구이지 거래 중개가 아님 (안 하기로 함)
- 네이티브 모바일 앱(App Store/Play Store 배포) — 반응형 웹 우선 (아직 안 함)

## 제약
- 로그인/계정 없이 커플이 데이터를 공유해야 한다 → **클라우드 공용 저장소 + 공유 코드** 방식 필요
- 모바일 우선 반응형 웹 (PC에서도 사용)
- 담당자 지정은 **단순 표기**일 뿐, 데이터 접근 권한을 제한하지 않는다

## 용어집
도메인 용어의 정의. **여기 정의된 이름이 03의 엔티티명·코드 식별자가 된다.**
| 용어 | 정의 |
|---|---|
| 준비영역 (Area) | 스드메·웨딩홀·신혼집 등 결혼준비 관리 영역 분류 태그. 모든 레코드에 하나씩 부착 |
| 담당자 (Assignee) | 체크리스트·일정의 책임 표기(나/애인/공동). 권한 제한이 아닌 단순 표기 |
| 분담 (Split) | 하나의 지출을 나/애인/양가가 각각 부담한 금액 |
| 로드맵 (Roadmap) | 결혼일 기준으로 역산한 준비 단계 타임라인 |
| 공유 코드 (Share Code) | 로그인 없이 같은 공용 저장소에 접속하기 위한 키/링크 |
| 시드 (Seed) | 앱이 기본 제공하는 한국 결혼준비 표준 체크리스트·로드맵 초기 데이터 |
| 길일 (吉日) | 만세력 기준 혼례에 좋은 날. 캘린더 날짜 셀에 표식해 날짜 선택을 돕는 참고 정보 |
