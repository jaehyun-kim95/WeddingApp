# Phase 2 — UI/UX 설계 완료 보고

## 개발 내용

디자인 시스템(`DESIGN.md` + `design/system.css`)을 확립하고, 9개 화면 전부를 정적 HTML/CSS
목업으로 설계·승인받았다.

| 화면 | 파일 | 핵심 구조 |
|---|---|---|
| 홈 | `home.html` | 디자인 시스템 기준(baseline). 마스트헤드+D-day 센터피스+미니 캘린더+바로가기 밴드 |
| 일정 | `schedule.html` | 캘린더↔리스트 세그먼트 뷰 전환, 길일 표시, 날짜 미정 안내 |
| 체크리스트 | `checklist.html` | 영역별 섹션+미니 미터 요약+영역 필터 칩 |
| 비용 | `budget.html` | 지출 단일 원장(ADR-0001), 업체별 기본+옵션→최종금액 묶음 |
| 업체 관리 | `vendors.html` | 정보 관리 전용(ADR-0001), 계약 패널+후보 리스트 |
| 하객 관리 | `guests.html` | 명단+축의금+식대, 관계 카테고리 다중 필터 드롭다운+그룹 스위치(순수 CSS) |
| 갤러리 | `gallery.html` | 영역별 사진 썸네일 그리드(이미지 격자 — 카드 그리드 금지의 예외) |
| 준비영역 모아보기 | `areas.html` | A(영역 상세)+B(전체 조망) 하이브리드, 순수 CSS 아코디언 |
| 설정 | `settings.html` | 결혼 정보·공유 코드·데이터·표시 옵션 |
| 더보기 메뉴 허브 | `more.html` | 탭바 "더보기" = 서브 화면(모아보기·업체·하객·갤러리) 메뉴 리스트 |

**네비게이션 모델 확정**(하이브리드, 사용자 결정): 탭바 5개(홈·일정·체크·비용·더보기). 더보기 탭은
메뉴 허브(`more.html`)로 서브 화면 진입을 모으고, 설정은 홈·더보기 허브 우측 상단 **톱니**로 진입.
두 가지 시안(A: 홈 톱니, B: 더보기 메뉴 허브)을 유즈케이스 흐름 비교 Artifact로 보여준 뒤 사용자가
하이브리드로 결정했다.

**디자인 검토**: `/impeccable audit design/`로 9개 화면(+더보기 허브) 전체를 접근성·성능·테마·
반응형·구현 일관성 5개 차원으로 점검. 상세는 아래 「검증 결과」.

## 이슈

- 체크리스트(`checklist.html`)에서 `flat-type-hierarchy` advisory 1건 검출 — `h3`(영역명)과 본문이
  둘 다 16px. 검토 결과 굵기(700 vs 400)로 위계가 구분되는 의도된 타입 램프(기존 승인 화면, `DESIGN.md`
  타입 스케일과 일치)로 판단해 **수정하지 않음**(advisory, 비차단).
- `more.html`·`areas.html`의 탭바 "더보기" 자기 탭이 `href="#"`(죽은 링크)였다 — 홈·일정·체크·비용
  4개 화면은 활성 탭도 실제 자기 URL을 갖는 확립된 패턴인데 이 둘만 어긋나 있었다.
- `areas.html`의 아코디언 chevron 회전 트랜지션에 `prefers-reduced-motion` 예외가 빠져 있었다 —
  같은 세션에서 만든 `guests.html`·`settings.html`의 스위치/드롭다운엔 있는데 누락.

## 트러블슈팅

- **탭바 자기 링크 불일치 발견 과정**: `/impeccable audit` 중 "구현 일관성" 차원을 보려고 전체 화면의
  `더보기` 탭 href를 `grep`으로 일괄 조회했다. 처음엔 전부 `more.html`로 가는 줄 알았는데, `more.html`
  자신과 `areas.html` 두 곳만 `href="#"`였다. 원인은 `home.html`/`budget.html` 등 "자기 탭도 실제 URL"
  패턴을 그대로 복붙하지 않고 "활성 탭이니 `#`이면 되겠지"로 새로 짰기 때문. 4개 기존 화면과 패턴을
  직접 비교해 정설을 확인한 뒤 고쳤다.
- **reduced-motion 누락 확인**: 전체 화면에서 `transition:` 보유 파일을 추려(`grep -l`), 그중
  `prefers-reduced-motion` 처리 파일과 차집합을 냈다. `gallery.html`·`vendors.html`·`checklist.html`도
  목록에 걸렸지만 내용을 보니 전부 `background`/`color` 페이드뿐(전정 자극성 모션 아님)이라 예외가
  필요 없는 기존 패턴과 일치 — 실제 누락은 `transform:rotate`를 쓰는 `areas.html` 하나뿐이었다.

## 사이드 이펙트 및 조치

- **`more.html` 파일 역할 교체**: 기존 "준비영역 모아보기"였던 `more.html`을 `areas.html`로 이동하고,
  `more.html`을 새로 "더보기 메뉴 허브"로 만들었다. `home.html`이 이미 준비영역을 `areas.html`로
  링크하고 있던 기존 불일치가 이 재배치로 자연히 해소됐다.
- **`home.html` 바로가기 밴드 변경**: 밴드 안에 있던 '설정' 항목을 제거하고(톱니로 대체), 마스트헤드
  우측에 설정 톱니(`.gear-btn`)를 추가했다. 홈을 쓰는 다른 화면 요소(`.cal`/`.list` 등 공유 컴포넌트)는
  건드리지 않았다 — 마스트헤드 레이아웃만 flex로 바꿔 톱니를 얹었다.
- **`.impeccable/config.json` 예외 등록**: `guests.html`·`gallery.html`·`areas.html`·`settings.html`
  신규/재배치 파일에 `cream-palette`·`cramped-padding` 표준 예외를 파일명 단위로 재등록(기존 승인
  화면들과 동일 사유).

## 검증 결과

### `/impeccable audit design/` — 5차원 점수

| # | 차원 | 점수 | 핵심 근거 |
|---|---|---|---|
| 1 | 접근성(A11y) | 3/4 | AA 대비는 `impeccable detect`로 전수 통과(과거 세션에 실제 저대비 버그 2건 발견·수정 이력 있음). 아이콘 전용 컨트롤(`.gear-btn`)엔 `aria-label`, FAB은 전부 가시 텍스트 동반. `prefers-reduced-motion` 처리(1건 누락 발견·수정). **남은 갭**: 체크박스·스위치·드롭다운 체크(`.check` 20×20, `.dd-box` 18×18, `.switch-track` 38×22)가 WCAG AA SC 2.5.8의 24×24px 최소 터치 타겟에 못 미친다 — 단, 현재는 정적 목업이라 실제 클릭 핸들러가 없어 "살아있는" 위반은 아니다. 3단계에서 실제 인터랙션을 붙일 때 히트 영역을 넓혀야 한다. |
| 2 | 성능 | 4/4 | JS 전혀 없음(순수 CSS `:checked`/`:has()` 토글), 이미지 없음(SVG 아이콘+CSS 그라디언트 플레이스홀더), 애니메이션은 전부 저비용 속성(`background`/`color`/`transform`)만 사용. 레이아웃 스래싱·번들 비대화 대상 자체가 없다. |
| 3 | 테마 | 3/4 | `system.css`의 CSS 커스텀 프로퍼티 토큰을 전 화면이 일관되게 사용(임의 hex는 갤러리 플레이스홀더에서 1건 발견돼 토큰으로 교체한 이력 있음). **다크 모드는 미구현** — 서피스 브리프에 "추후 결정"으로 명시된 열린 결정이라 오류가 아니라 의도된 범위 밖. |
| 4 | 반응형 | 3/4 | 모바일 390~430px 1차 타겟 + 데스크톱 600px 이상 앱 셸 분기(`body` 패딩+`.app` 라운드+탭바 `sticky`)가 `system.css`에 있다. 가로 스크롤은 `.filter-scroll`/`.quicknav`/`.photo-strip` 전용 컨테이너 안에만 있고 페이지 레벨 가로 스크롤은 없음. 터치 타겟 실측(필터 칩 52×34, FAB 126×52, 탭바 아이템 86×57)은 모두 24×24 최소치를 넉넉히 통과. 체크박스류는 위 1번과 동일 갭. |
| 5 | 구현 일관성 | 4/4 | `impeccable detect` 결과: 10개 파일 중 9개 0건, 1개(`checklist.html`) advisory 1건(검토 후 의도된 것으로 판단, 비차단). 감사 중 **진짜 버그 2종 발견·수정**: ① `more.html`·`areas.html`의 "더보기" 탭 자기 링크가 `href="#"`로 확립된 패턴(자기 탭도 실제 URL)과 어긋남 → 고침. ② `areas.html` 아코디언 애니메이션에 reduced-motion 예외 누락 → 고침. 공유 컴포넌트(필터 칩·FAB·스위치·리스트 행)가 화면 간 일관되게 재사용됨. 목업 데이터는 전부 현실적인 한국 결혼준비 맥락(placeholder/lorem 없음). |
| **합계** | | **17/20** | **Good**(14-17 밴드, Excellent 경계) |

### 구현 일관성 판정(Pass)
9개 화면 + 더보기 허브가 하나의 디자인 시스템(색·타이포·반경·간격 토큰, 헤어라인 리스트 구조,
칩/FAB/스위치/아코디언 공유 컴포넌트)을 일관되게 표현한다. 감사 중 발견한 2건의 실제 결함은 전부
그 자리에서 수정하고 재검증했다.

### 실측 확인 항목
- `impeccable detect --json`을 10개 파일 전부에 개별 실행 — 9개 0건, 1개 advisory 1건(비차단).
- 브라우저 실측(Chrome): 홈 톱니→설정, 더보기 탭→메뉴 허브, 메뉴→준비영역 모아보기(`areas.html`)
  3개 핵심 흐름을 실제 클릭으로 왕복 확인.
- 터치 타겟 크기: `getBoundingClientRect()`로 필터 칩·체크박스·FAB·탭바 아이템 4종 실측.
- 탭바 "더보기" href 전수 조사(`grep`)로 10개 파일 링크 일관성 확인.

### 미검증으로 남은 것
- **실제 디바이스/스크린리더 테스트**: 터치 타겟·키보드 포커스·VoiceOver/TalkBack 동작은 브라우저
  에뮬레이션·DOM 실측까지만 했고, 실기기에서는 확인하지 않았다.
- **체크박스류 터치 타겟 확장**: 위 표에 적은 대로, 실제 인터랙션(클릭 핸들러·상태 저장)이 붙는
  3단계 개발 시점에 `.check`/`.dd-box`/`.switch-track`의 히트 영역을 24×24px 이상으로 넓히는 작업이
  필요하다 — `04-dev-plan.md`에 반영 대상.
- **다크 모드**: 서피스 브리프에 "추후 결정"으로 열려 있다. 2단계에서는 다루지 않았다.
