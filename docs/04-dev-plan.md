# 개발계획

> 여기엔 **순서와 판정 기준**, 그리고 빌드를 이끄는 **핵심 프로세스 흐름**을 쓴다. 설계 내용은 `01`~`03`,
> 완료 보고는 `reports/`에 쓴다. 디렉터리 구조·계층은 [`02-architecture.md`](02-architecture.md)가 단일 출처.

## Phase 개요

핵심(홈·일정·체크·비용)부터 완성하고 확장한다(`PRODUCT.md` 원칙 5). 각 Phase는 **검증 체크리스트를
전부 통과해야** 다음으로 간다.

| Phase | 목표 | 선행 조건 | 상태 |
|---|---|---|---|
| 0 | 개발 기반 — 디자인 토큰·공용 컴포넌트·네비 뼈대·Supabase 연결·공유코드 온보딩 | scaffold 완료 | ✅ ([보고서](reports/phase-0.md)) |
| 1 | 코어 화면 — 홈·일정·체크리스트·비용 (실데이터 CRUD) | Phase 0 | 🟡 네 화면 구현 완료, Realtime 2기기 검증 보류 ([보고서](reports/phase-1.md)) |
| 2 | 정보/장부 — 업체·하객(엑셀 I/O)·갤러리(사진 업로드) | Phase 1 | ⬜ |
| 3 | 재조합·운영 — 준비영역 모아보기·설정·표준 시드·알림 | Phase 2 | ⬜ |
| 4 | 배포 — EAS 내부 배포 + GitHub 연동 OTA, 두 기기 실사용 | Phase 3 | ⬜ |

## Phase 0 — 개발 기반
**산출물**: 앱이 기기에서 5개 탭을 오가고(서브 화면 push 포함), 공유 코드로 Supabase에 접속해 빈
데이터를 읽어오는 상태. 디자인 토큰과 공용 컴포넌트가 DESIGN.md를 따른다.

- `constants/theme.ts`를 DESIGN.md 토큰(색·타이포 11단계·간격·반경 5단계)으로 교체.
- 공용 컴포넌트 프리미티브: `chip`·`meter`·`fab`·`list-row`·`switch`·`segmented`·`page-head` 등
  (DESIGN.md 규범, **터치 타겟 히트 영역 ≥24×24px** — `phase-2.md` 미검증 항목 해소).
- 네비 뼈대: `app/(tabs)/_layout.tsx`(NativeTabs 5개) + 루트 Stack에 서브 화면(areas·vendors·guests·
  gallery·settings) + `onboarding`. 네비게이션 모델은 CLAUDE.md 「네비게이션 모델」 준수.
- `lib/supabase.ts`(anon 클라) + `lib/rpc.ts`(공유코드 게이트웨이) + `lib/share-code.ts`(저장/로드) +
  `lib/query-client.ts`. Supabase 프로젝트 생성 + 스키마 v1 마이그레이션(`docs/db/`) 적용 + 시드 투입.
- `types/db.ts`: 03 데이터 모델 → TS 타입.
- **ADR-0003 작성**: RLS RPC 게이트웨이 함수 설계 확정(`docs/db/access-control-rls.md`가 플래그한 항목).

**검증 체크리스트** — 전부 통과해야 완료.
- [x] `npx tsc --noEmit` 0에러 (교체한 실제 코드 기준 — scaffold 예제 제거 후)
- [x] `npx expo-doctor` 통과 (`npx expo install --fix`로 SDK 58 드리프트 7건 정렬 → 20/20)
- [x] 실기기에서 5개 탭 전환 + 서브 화면 push/back 동작(Expo Go 터널 ngrok QR 접속, 사용자 실기기 통과 2026-11-06)
- [x] 온보딩에서 새 공유 코드 발급 → 저장 → 재실행 시 자동 접속 확인(웹 프리뷰 실측 통과)
- [x] 공유 코드로 RPC 호출 시 그 커플 데이터만 반환, 틀린 코드는 0건 반환(실측 쿼리로 격리 검증)
- [x] 공용 컴포넌트 터치 타겟 ≥24×24px (DOM/좌표 실측)

## Phase 1 — 코어 화면 (홈·일정·체크·비용)
**산출물**: 네 화면이 실데이터로 동작한다. 두 기기에서 같은 데이터가 실시간 동기화된다.

- 체크리스트: 영역 필터·완료 토글(낙관적)·추가/수정/삭제, 담당자 표기.
- 일정: 월간 캘린더(일정·마일스톤)·리스트 뷰, 날짜 미정 모드, 길일 표시(토글 연동). 비용·업체
  교차 참조(`payment.due_date`·`vendor.contract_date`를 일정 타임라인에 병합 표시)는 Phase 1
  범위 밖으로 디퍼했다(사용자 결정 2026-11-08) — `selectAgenda`가 `TimelineItem` 통합 뷰 타입으로
  반환하도록만 설계해, 필요해지면 비용 화면 데이터를 같은 모양으로 합류시킬 수 있게 열어 뒀다.
- 비용: 지출 원장(기본+옵션→최종금액), 분담(행 저장), payment 실지출/약정 집계, 영역 소계.
- 홈: D-day·진행률·예산 소비율·다음 할 일·미니 캘린더 — 위 데이터의 집계 뷰.

**검증 체크리스트**
- [x] `npx tsc --noEmit` 0에러
- [x] 각 화면 CRUD(처음/중간/끝 경계 포함)가 기기에서 동작(실측)
- [ ] 두 기기(또는 두 세션)에서 한쪽 변경이 Realtime으로 반대쪽에 반영(실측) — **미검증**(사용자 확인
      2026-11-11: 아직 두 기기로 동시 사용해 본 적 없음). Phase 0에서 브로드캐스트 채널 인프라
      자체는 격리 실측됐으나, 화면별 실사용 중 교차 반영은 따로 확인된 적 없다.
- [x] 비용 집계 불변식(최종금액=기본+옵션, 실지출=납부완료 합) 단위 테스트 통과
- [x] 멱등성·보존성 테스트(두 번 실행·개수 보존) 통과

**완료 보고**: [reports/phase-1.md](reports/phase-1.md)

## Phase 2 — 정보/장부 (업체·하객·갤러리)
**산출물**: 업체 정보 관리, 하객 명단+축의금+엑셀 I/O, 갤러리 사진 업로드/분류. 세 기능은 서로 독립된
슬라이스라 체크리스트도 기능별로 나눠 진행 상태를 추적한다.

- 업체: 영역별 후보/계약, 역할(스드메 하위), 계약 견적 참고값(금액 소스 아님 — ADR-0001).
- 하객: 측/관계 필터·그룹, 참석·축의금·식대, 엑셀 가져오기/내보내기(SheetJS + Expo 공식 모듈, ADR-0006).
- 갤러리: 영역별 썸네일 그리드, 사진/영상 업로드(expo-image-picker → Supabase Storage),
  저장 위치 정책(ADR-0002 — 1GB 초과 시 외부 전환 결정 지점).

**검증 체크리스트 — 하객**
- [x] `npx tsc --noEmit` / `jest` / `eslint` 0에러
- [x] CRUD + 측·관계 필터·그룹 동작(실측, 레이아웃·FAB 겹침·측별 대시보드 요약 버그 수정 포함)
- [x] 금액 입력 100원 단위 정밀도(식대 단가·축의금, `lib/money.ts` 공용화) 실측
- [ ] 엑셀 가져오기→미리보기→일괄 저장, 내보내기 왕복 무손실 — **순수 파싱 로직(병리 입력 포함)은
      단위테스트로 검증 완료, 실기기 파일 피커·공유 시트 플로우는 미검증**(사용자 확인 2026-11-12)
- [ ] Realtime 2기기 교차 반영(Phase 1과 동일 사유로 보류)

**검증 체크리스트 — 업체·갤러리**
- [ ] `npx tsc --noEmit` 0에러
- [ ] 업체 CRUD + 필터/그룹 동작(실측)
- [ ] 사진 업로드→Storage 저장→썸네일 표시, 영역 분류 동작(실측)

**완료 보고**: [reports/phase-2-dev.md](reports/phase-2-dev.md) — 업체·갤러리까지 끝나야 작성한다
(하객 단독 구현 세부는 `02` 「구현 함정」·`docs/db/table-definitions.md`·git log가 갖고 있다).

## Phase 3 — 재조합·운영 (모아보기·설정·시드·알림)
**산출물**: 준비영역 크로스컷 뷰, 설정 전반, 표준 시드 불러오기, 길일·납부 알림.

- 준비영역 모아보기(areas): 영역별 할일·일정·업체·비용·사진 집계 아코디언.
- 설정: 결혼 정보 편집·공유 코드 표시/재발급·백업 내보내기/가져오기(schema_version)·표시 토글.
- 표준 시드 불러오기: seed_* → 결혼일 역산 → couple 데이터로 복사.
- 알림: `expo-notifications`로 납부일 알림(토글 연동), 길일 표시.

**검증 체크리스트**
- [ ] `npx tsc --noEmit` 0에러
- [ ] 모아보기 집계 수치가 각 원본 화면과 일치(실측 대조)
- [ ] 시드 불러오기 멱등성(두 번 불러도 중복 안 생김) 테스트 통과
- [ ] 백업 내보내기→가져오기 왕복 + **직전 버전 백업 읽기**(하위 호환) 테스트 통과
- [ ] 납부일 알림이 due_date 기준으로 스케줄됨(실측)

**완료 보고**: [reports/phase-3.md](reports/phase-3.md)

## 핵심 프로세스 흐름

빌드를 이끄는 6개 흐름(온보딩·낙관적 CRUD·실시간 동기화·시드 로드·비용 집계·배포)은 **별도 산출물
폴더 [`flows/`](flows/)** 로 분리했다 — 각 흐름을 `.mmd`(소스) + `.svg`(렌더 이미지)로 관리한다.
인덱스·전체 렌더는 [flows/README.md](flows/README.md). 세부 저장 구조는 [`db/`](db/), 화면 규칙은
`design/` 목업 참조.
