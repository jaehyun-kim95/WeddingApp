# 비용 화면 — 대시보드 구분 · 아코디언 · 영역 필터 · 예산 표기 개선 설계

## Context

비용 화면 실구현(기본 CRUD·납부/잔금 모델)은 완료됐지만, 실사용 피드백(2026-11-10)으로 4가지
문제가 드러났다.

1. 상단 대시보드 지표가 "예산·약정·잔여"라 **지금까지 얼마나 냈는지**가 안 보인다.
2. 대시보드(현황)와 지출 목록(입력)이 같은 배경에 이어져서 "보는 곳"과 "만지는 곳"이 구분이 안 된다.
3. 지출 카드(VendorGroup)마다 기본견적·옵션 라인이 항상 펼쳐져 있어 지출이 많아지면 스크롤이 길어진다.
4. 영역이 항상 6개 다 보여서, 한 영역만 보고 싶을 때 걸러볼 방법이 없다.

**UI 선택지는 웹 목업(`design/budget-dashboard-variants.html`)으로 제시하고 사용자가 고른 방향으로
확정했다**(상시 방침, [[ui-choices-as-web-mockups]] 메모리). 아래 「결정된 방향」은 전부 그 목업을
보고 사용자가 고른 것이다.

## 결정된 방향 (사용자 승인 완료, 2026-11-10)

### ① 대시보드 ↔ 입력 영역 구분 — C안(흰 표면 카드)
대시보드(예산 요약 + 분담 정산)를 `colors.surface` 흰 패널(헤어라인 보더 `lineStrong`, 그림자 없음)로
감싼다. 이미 캘린더 패널에서 승인된 "패널은 흰 배경" 규범과 동일 규칙이라 새 색 규칙을 늘리지 않는다.
그 아래 영역별 배분(지출 목록)은 배경(`colors.ground`) 그대로 둬서 "보는 패널 vs 만지는 목록"을 구분한다.

### ② 상단 지표 — 약정 | 납부 | 잔여
- **약정** = 기존과 동일(기본견적+옵션 합, `committed`).
- **납부** = 완료된 payment 합(`actualSpent`, 기존 "실지출"과 동일 값, 라벨만 변경).
- **잔여** = `Math.max(0, committed − actualSpent)`(아직 못 낸 총액, 과납이면 0 클램프 — 개별 지출
  `VendorGroup.remaining`과 동일한 클램프 규칙). **기존 "잔여"(= totalBudget − committed)와 의미가
  다르다** — 상단 3값에서 "예산"이 빠지므로 예산 비교는 ④ 캡션으로 이동한다.

### ③ 지출 카드 아코디언 — 접힘 요약 압축 + 펼침 상세
- **접힘(기본)**: 이름 한 줄 + **"약정 X · 납부 Y · 잔금 Z" 한 줄**만. 기존의 3셀 박스·미터는 제거
  (사용자 피드백: "프로그레스바 제거", "한 줄로 표현").
- **펼침(헤더 탭)**: 기본견적·옵션 라인 노출 + 하단 **"수정 →"** 링크.
- **편집 진입점이 바뀐다**: 기존엔 카드 전체 탭 = 편집 모달(`ExpenseDetail`)이었다. 이제 **헤더 탭 =
  아코디언 토글**, **"수정" 링크 탭 = 편집 모달**로 분리한다.
- 아코디언 열림 상태는 카드별 로컬 UI 상태(저장 안 함, 셀렉터·캐시 영향 없음).

### ④ 예산 비교 표기 — 1안(상시 캡션 한 줄)
대시보드 패널 맨 아래에 "참고 · 예산 대비 약정 {budgetRate}% · 예산 {totalBudget}" 캡션을 항상
노출한다(기존 `budget-summary.tsx`의 참고 캡션과 거의 동일 — ①②로 상단 3값 배치가 바뀌는 것 외엔
캡션 로직은 유지). 예산 수치를 탭하면 기존처럼 `AmountEditModal`로 수정.

### ⑤ 영역 드롭다운 필터 — 다중 선택, 빈 선택 = 전체
영역별 배분 목록 위에 "영역 ▾" 드롭다운을 추가한다. 하나 이상 체크하면 그 영역만 노출, 아무것도
안 체크하면 지금처럼 6개 영역 전부 노출(하객 화면의 관계 필터와 동일한 OR 규칙, 단 RN엔 `:has()`가
없으므로 로컬 `useState`로 구현).

## 데이터/셀렉터 변경

- **`BudgetSummary.remaining`의 의미를 변경한다(breaking)**: `totalBudget − committed` →
  `committed − actualSpent`. 기존 의미는 `grep` 확인 결과 `budget-summary.tsx`의 상단 "잔여" 셀
  외에는 쓰이지 않으므로 안전한 재정의다. `totalBudget`·`budgetRate`는 캡션(④)에서 그대로 쓰이므로
  필드 자체는 유지한다.
- 영역 필터는 **셀렉터 변경 없이** 화면(`budget.tsx`)에서 `breakdown` 배열을 클라이언트 필터링한다
  (스냅샷·RPC·캐시 전부 무영향).
- `VendorGroup`/`AreaBreakdown`의 `paid`/`remaining`(개별 지출 잔금) 계산은 변경 없음.

## 컴포넌트 변경

| 파일 | 변경 |
|---|---|
| `budget.tsx` | `BudgetSummary`+`Settlement`를 흰 카드 View로 감쌈(①). 영역 필터 `useState<Set<string>>` 추가, `breakdown`을 필터링해 렌더(⑤). |
| `budget-summary.tsx` | 상단 3셀을 약정\|납부\|잔여로 재배치(②). 캡션 줄은 유지(④). |
| `vendor-group.tsx` | 3셀+미터 제거 → 한 줄 요약(③ 접힘). 로컬 `open` 상태 추가, 헤더 탭=토글. 기본견적/옵션 라인 + "수정" 링크를 펼침에만 노출, 링크 탭이 `onEdit` 호출(③ 펼침). |

## 테스트 변경

- `api.test.ts`의 `selectBudgetSummary` 관련 전체 재작성: `remaining`을 `Math.max(0, committed −
  actualSpent)` 기준으로, 경계 케이스(약정 0, 완납, 전액 미납, 과납 시 0 클램프)를 포함.
- 아코디언 열림 상태·드롭다운 선택 상태는 로컬 UI 상태라 프로젝트 관례상 RN 컴포넌트 프레젠테이션
  테스트를 추가하지 않는다(기존 컴포넌트들도 동일 — 셀렉터/리듀서만 유닛 테스트 대상).

## 하지 않는 것

- vendors 화면 본구현(계속 범위 밖).
- 영역 필터의 서버 측 저장(항상 클라이언트 전용, 화면 벗어나면 초기화).
- 개별 지출 잔금(`VendorGroup.remaining`) 계산 로직 변경 — 이번 작업은 집계 표기·레이아웃만 다룬다.
