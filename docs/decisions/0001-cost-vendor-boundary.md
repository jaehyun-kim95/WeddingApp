# ADR-0001: 업체·비용 경계 — 비용 중심 통합(지출 원장은 비용, 업체는 정보)

- **상태**: 채택 (2026-11-02)
- **맥락**: 업체(스드메 등)는 업체마다 기본 견적에 추가 옵션이 붙어 최종 금액이 변동하고,
  한 영역에 여러 업체(스드메=스튜디오·드레스·메이크업)가 각각 계약된다. 이 금액·옵션을 업체
  화면과 비용 화면 **양쪽에서 각각** 다루면 같은 지출이 두 곳에 중복 저장되어 서로 어긋난다
  (실제로 목업에서 업체·비용에 금액을 따로 적어 모순이 드러났다). "한 번 저장, 여러 번 조합"
  (PRODUCT.md 원칙 1)에 따라 지출은 하나의 진실이어야 한다. 어느 화면을 금액의 소스로 둘지,
  옵션(최종금액 변동)을 어디서 관리할지 정해야 했다.
- **결정**: **비용을 지출의 단일 진실(원장)로 둔다.**
  - 금액·옵션·최종금액·분담은 **비용 화면에서** 관리한다. 지출은 업체별로 묶고, 각 업체는
    기본 견적 + 추가 옵션들로 **최종금액**을 이루며(옵션 추가 시 최종금액 증가), 영역 합계·전체
    합계로 집계한다. 예산 대비·분담(나/애인/양가)도 비용 소관.
  - **업체 화면은 '정보' 관리**로 한다 — 후보 비교, 계약 상태(후보/계약), 계약일, 위치, 역할
    (스드메 하위: 스튜디오/드레스/메이크업), 연락 메모. 업체 화면은 금액의 소스가 아니며, 계약
    견적은 참고값으로만 보이고 금액 상세(옵션·납부 집계)는 비용에서 본다.
  - 두 화면은 같은 데이터를 다른 축으로 보는 뷰다(업체=공급자/계약 관점, 비용=예산/분담 관점).
    업체의 계약·납부 **일정**(언제)은 일정 화면과 연동되고, 납부 **금액·집계**는 비용이 맡는다.
- **버린 안**:
  - **역할 분리 + 연동(업체가 금액의 원천, 비용은 집계·분담 뷰)** — 업체에서 옵션·최종금액·납부를
    관리하고 비용은 그것을 집계. 설계적으로 깔끔하나, 사용자가 "옵션으로 최종금액이 느는 관리는
    비용에서 하고 싶다"고 명시적으로 선택해 버렸다. (제안자 추천안이었음)
  - **업체 중심 통합(금액·옵션·납부는 업체에서만, 비용은 요약 뷰만)** — 분담·예산 정산이 업체
    화면에 섞여 업체가 비대해지고, "예산 안에서 얼마·누가"라는 비용 본연의 관점이 약해져 버렸다.
- **결과**:
  - 비용 화면이 지출 원장이 되어, 업체별 기본+옵션→최종금액 구조와 옵션 추가 UI를 갖는다
    (화면이 더 무거워지는 비용을 감수). 업체 화면은 가벼워지고 금액 상세를 들어낸다.
  - **새 제약**: 금액은 비용에만 저장한다. 업체 화면에 금액을 다시 적어 두 곳이 어긋나게 하지
    않는다 — 업체는 참고값(계약 견적)만 표시하고 상세는 비용을 가리킨다.
  - `docs/01-requirements.md`의 업체·비용 범위를 이 경계에 맞춰 갱신한다.
