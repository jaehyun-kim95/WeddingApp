# ADR-0005: 비용 진행률·분담 표기 기준 — 실지출 기준 메인 지표, 실납부자 라벨링

- **상태**: 채택 (2026-11-10)
- **맥락**: 비용 화면과 홈 대시보드에 보여줄 "진행률" 퍼센트 후보가 두 가지였다 — ① spentRate =
  실지출(납부완료 합) ÷ 약정(지출내역 총합), ② budgetRate = 약정 ÷ 예산. 처음엔 budgetRate를
  "예산 소비율"이라는 이름으로 메인 미터에 썼는데, 홈 대시보드에 같은 자리를 다른 라벨("지출
  진행률")로 넣으려다 두 화면이 같은 자리를 다른 값으로 부르는 모순이 드러났다. 같은 세션에 분담
  정산(ADR-0004)의 payer 값(ME/PARTNER/BOTH_FAMILY)을 화면에 "나/애인"으로 라벨링하면 공유 코드로
  접속한 두 사람이 같은 데이터를 서로 다르게 읽게 된다는 점도 드러났다.
- **결정**:
  - 메인 진행률(비용 화면 상단 + 홈 대시보드 지출 미터) = **spentRate(실지출÷약정)**로 통일,
    라벨도 "지출 진행률"로 통일한다. budgetRate(약정÷예산)은 대시보드 하단 참고 캡션으로만
    격하한다("참고 · 예산 대비 약정 N% · 예산 M") — 메인 미터에 다시 쓰지 않는다.
  - `BudgetSummary.remaining` = `Math.max(0, 약정 − 납부)`(미납 총액). "예산 − 약정" 비교는
    budgetRate 참고 캡션이 전담한다.
  - 분담 정산 라벨은 payer DB 값은 그대로 두고 화면 라벨만 **"신랑/신부/양가"**로 고정한다 —
    "나/애인"은 보는 사람에 따라 바뀌는 상대적 기준이라 공유 코드 앱에 부적합하다. `payer=null`
    (미지정) 완료 납부도 분담 정산에 **별도 행으로 노출**한다(숨기면 그 금액이 안 보이게 된다).
- **버린 안**:
  - budgetRate를 메인 지표로 유지 — 예산을 안 정한 영역이 있으면 분모가 흔들려 실사용 테스트에서
    설득력이 떨어졌다.
  - payer=null 납부를 숨김 — 분담 행 합계가 전체 실지출과 안 맞아 보이는 혼란을 야기했다.
- **결과**: 비용 화면과 홈 대시보드가 같은 셀렉터(`selectBudgetSummary.spentRate`)·같은 라벨을
  공유해 화면 간 수치 불일치가 사라졌다. **새 제약**: budgetRate를 메인 미터에 다시 끌어오지
  않는다 — 끌어오면 이 ADR이 해결한 모순이 재발한다.
