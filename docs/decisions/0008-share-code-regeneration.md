# ADR-0008: 공유 코드 재발급 — 즉시 교체(토큰 이원화 없음)

- **상태**: 채택 (2026-11-16)
- **맥락**: 설정 화면에서 공유 코드를 재발급하는 기능이 필요하다(코드가 유출됐거나 바꾸고 싶을 때).
  이 앱은 Auth가 없고(ADR-0002) `couple.share_code`가 곧 접속 비밀이자 격리 키다(ADR-0003). 재발급
  시점에 두 사람 중 한쪽만 앱을 열고 있고, 다른 쪽은 재발급 사실을 실시간으로 알 길이 없다(Realtime
  브로드캐스트는 이미 연결된 세션에만 신호가 가고, 연결이 끊긴 세션에는 전달되지 않는다).
- **결정**: 재발급 = **교체**. `regenerate_share_code(old_code)`가 `couple.share_code`를 새 코드로
  덮어쓰고 새 코드를 반환한다. 옛 코드는 그 순간부터 완전히 무효(`get_couple_snapshot`이 PT401)가
  된다. 재발급을 누른 쪽은 클라이언트가 응답으로 받은 새 코드로 즉시 자동 전환(`ShareCodeProvider.
  save`)되지만, **상대방은 수동으로 새 코드를 다시 입력해야 한다** — 앱이 이를 알려줄 방법이 없어
  UI에서 재발급 전 확인 다이얼로그로 이 트레이드오프를 명시한다("재발급하면 기존 코드로 접속 중인
  상대방은 새 코드를 다시 입력해야 합니다").
- **버린 안**:
  - **이원 토큰(옛 코드 유예 기간 동안 병행 유효)** — 재발급 후에도 옛 코드를 일정 시간(예: 24시간)
    동안 같이 살려두면 상대방이 자연스럽게 넘어올 시간을 번다. 하지만 "코드가 유출돼서 급히 막아야
    하는" 가장 흔한 재발급 이유와 정면으로 충돌한다(유예 기간 동안 유출된 옛 코드로 계속 접근 가능).
    이 앱의 공유 코드는 비밀번호에 가까운 유일한 보안 경계라 "즉시 무효"가 아니면 재발급의 의미가
    없다.
  - **상대방에게 알림 전송(푸시/이메일)** — Auth도 서버도 없는 구조라(ADR-0002) 상대방을 식별할
    연락처 자체가 시스템에 없다. 알리려면 이메일/전화번호 수집이라는 새 데이터 수집 범위가 생겨
    "로그인 없이 공유 코드만으로" 쓰는 이 앱의 핵심 설계와 어긋난다.
- **결과**: 재발급은 **파괴적 행위**로 취급해 확인 다이얼로그를 반드시 거친다(이미 Part B 공통
  규칙이 요구하는 수준과 일치). 두 사람이 메신저 등으로 직접 새 코드를 다시 공유해야 하는 수동
  동기화 비용이 남지만, 이 앱의 사용자는 "나 + 애인" 둘뿐이라 실시간 채널로 바로 알려줄 수 있어
  감수할 만한 비용으로 판단했다. 새로운 제약: 재발급 직후 상대방이 코드를 모른 채 앱을 계속 쓰면
  매 요청이 PT401로 실패하므로, 클라이언트는 이 에러를 받으면 온보딩(코드 재입력) 화면으로 분기해야
  한다(기존 `ShareCodeInvalidError` 처리 경로가 이미 이 역할을 한다 — 새 분기 추가 불필요).
