개발(12 Task, Task별 implementer+스펙 검토+코드 품질 검토 2단)로 구현 — `tsc`/`jest`(220개)/
`eslint` 0, `0008_gallery.sql` 적용 확인, 웹 프리뷰+브라우저 자동화로 업로드→그리드 반영→전체화면
보기→삭제→영역 필터까지 실측 통과. 과정에서 발견한 버그 2건(Storage RLS가 `couple` 자체 RLS

Claude가 자동화 도구로 한 검증이고, 사용자 본인이 실제로 써보고 승인한 적은 아직 없다** —
2026-11-14 세션 종료 시점에 사용자가 "갤러리 테스트 아직 승인 안 했다"고 명시적으로 확인함.
**다음 세션의 최우선 작업은 Phase 3 착수가 아니라, 사용자가 갤러리를 직접 테스트할 수 있게
돕고(Expo 개발 서버 안내, 질문 응대, 버그 있으면 재현·수정) 승인을 받는 것**이다. 승인이 나야만
Phase 3(준비영역 모아보기·설정) 착수 여부를 물어보는 단계로 넘어간다(§4). 하객 엑셀 플로우·갤러리
피커 권한 플로우·800MB 경고 배너는 여전히 실기기 미검증으로 남아 있다(§4).

## 1. 먼저 읽을 것 (이 순서로)

**지금 당장 할 일은 갤러리 사용자 승인을 기다리거나 돕는 것**이다 — Phase 3 착수는 그 다음이다.
업체 테스트(§2)는 전부 끝나 사용자 승인도 받았지만, **갤러리(§2-2)는 자동화 실측만 끝났고 사용자
승인 전**이니 혼동하지 않는다.

1. `CLAUDE.md`의 **「현재 상태」·「진행 현황」·「알려진 이슈」·「아키텍처」** — 지금 어디까지 됐고
   다음에 뭘 할지 + RN 코드/Supabase/금액 입력 **함정**(단일 출처, `02-architecture.md` 「구현 함정」에
   모여 있다). 특히 아래는 Phase 3(준비영역 모아보기·설정) 작업에서 재현될 수 있는 함정이라 꼭
   먼저 본다:
   - **탭 밖 push 화면 패턴**(`02` RN 앱 코드 섹션) — 모아보기도 업체·하객·갤러리와 같은
     `_layout.tsx` 루트 `Stack`(`headerShown:true`) 아래 push 화면이다(설정은 톱니로 진입, 별도
     확인 필요). 네이티브 헤더가 이미 제목+뒤로가기를 그리므로 화면 안에서 `PageHead`를 또 쓰지
     않는다. `Fab`는 `bottomInset={useSafeAreaInsets().bottom}`을 반드시 넘긴다.
   - **Supabase 마이그레이션은 CLI로 자동 적용되지 않는다** — 이 저장소엔 `supabase/config.toml`이
     없다(CLI 링크 안 됨). 새 마이그레이션(`000N_*.sql`)은 **사용자가 Supabase 대시보드 SQL
     Editor에 직접 붙여넣어 실행**해야 한다. 체크리스트·일정·비용·하객·업체·갤러리 6개 feature의
     `hooks.ts`는 실패 시 `Alert`로 원인을 보여주므로, 마이그레이션 미적용이면 저장 시도할 때 바로
     에러 메시지가 뜬다.
   - **Pressable 중첩 금지**(업체 0007 테스트에서 실측 발견, `02` 업체 서브섹션) — 카드 전체를
     `accessibilityRole="button"` Pressable로 감싸고 그 안에 보조 액션 버튼을 또 Pressable로 넣으면
     웹에서 `<button>` 안 `<button>` hydration 에러가 난다.
   - **영역 필터의 빈 상태는 필터링 후 데이터 기준으로 판단**(업체 0007 테스트에서 실측 발견,
     갤러리도 처음부터 `hasVisiblePhotos`로 재사용) — 모아보기도 영역별 뷰를 쓰면 같은 함정을 피한다.
   - **Storage RLS 정책에 다른 테이블 조회를 넣을 땐 `security definer` 함수로 분리**(갤러리
     0008에서 실측 발견, `02` 갤러리 서브섹션) — 정책 본문의 서브쿼리는 `anon` 권한으로 돈다.
2. **체크리스트·일정·비용·홈·하객·업체·갤러리 일곱 슬라이스 = Phase 3 화면의 템플릿**:
   `src/features/{checklist,schedule,budget,home,guests,vendors,gallery}/`(`api.ts` 셀렉터+쓰기·
   `cache.ts` 낙관적 캐시 리듀서·`hooks.ts` Query/Mutation+`Alert` 에러 표시·`components/`) 구조와
   `src/features/README.md`(도메인 파일 계약)를 먼저 본다.
3. **개발 계획**: `docs/04-dev-plan.md` — Phase 2(하객·업체·갤러리) 체크박스는 전부 찼다(엑셀/피커
   권한 플로우만 미검증). **Phase 3(모아보기·설정) 체크박스는 아직 없다** — 착수 전 설계 인터뷰부터
   필요할 수 있다(하객·갤러리 선례처럼).
4. **결정 이유**: `docs/decisions/` — ADR-0007(갤러리 Storage 접근 모델)이 가장 최근.

## 2-2. 지난 작업(구현+자동 실측 완료, **사용자 승인 대기 중**) — 갤러리(gallery) 서브에이전트 구동 개발

설계 스펙(`docs/superpowers/specs/2026-11-13-phase2-gallery-slice-design.md`)+계획
(`docs/superpowers/plans/2026-11-13-phase2-gallery-slice.md`, 12 Task)을 먼저 쓰고, Task마다
implementer 서브에이전트 → 스펙 검토 서브에이전트 → 코드 품질 검토 서브에이전트 순으로 진행했다
(`superpowers:subagent-driven-development`). 리뷰에서 발견해 즉시 수정한 버그 2건:

1. **Critical** — Storage RLS 정책(`photos_insert`/`photos_delete`)이 정책 본문에 `couple` 테이블을
   직접 조회하는 서브쿼리를 썼는데, `couple`엔 `anon` 정책이 없어(0001) 그 서브쿼리가 `anon` 권한으로
   돌면서 **항상 0행 → 항상 거부**됐다. 업로드/삭제가 100% 실패했을 버그. `couple_exists(text)
   returns boolean security definer` 함수로 분리해 고쳤다(`0008_gallery.sql`, `docs/02-architecture.md`
   갤러리 서브섹션에 재사용 가능한 패턴으로 기록).
2. `expo-image-picker@~58.0.10`의 `MediaTypeOptions.Images`가 이미 폐기(deprecated)돼 런타임 경고를
   띄우는 걸 발견 — `mediaTypes: ['images']`로 교체.

**실측(2026-11-13~14, 웹 프리뷰+브라우저 자동화)**: `0008_gallery.sql` 적용 확인(RPC 프로브로 PT401,
Storage 오브젝트 GET이 "Object not found"로 응답해 버킷 존재 확인) → 빈 상태 → 업로드(기기 갤러리
선택은 `<input type=file>`에 `change` 이벤트를 스크립트로 직접 디스패치해 우회, §3 참고) → 그리드
반영(통계 "전체 1장"·"원본 보관 0.0MB" 갱신) → 전체화면 보기(실제 공개 URL에서 이미지 로드 확인,
`couple.id` 경로 포함) → 삭제(Storage 오브젝트+`photo` 행 둘 다 제거를 `curl`로 재확인) → 영역 필터
(빈 영역 선택 시 안내 문구 정상 노출, 업체 버그 재발 없음) 전부 통과.

**미검증으로 남은 것**: 실기기(Expo Go)에서의 네이티브 파일 선택 다이얼로그·최초 권한 팝업 UX(웹
우회 테스트는 이 경로를 안 탄다), 800MB 이상 시 용량 경고 배너의 실제 노출(경계값 단위테스트로만
검증, 서비스 롤 키 없이 `size_bytes`를 강제로 키울 방법이 없음 — 사진이 자연스럽게 쌓이는 시점에
확인).

`docs/04-dev-plan.md` 갤러리 체크박스는 Claude 자동화 실측 기준으로 반영했다. **다음 세션에서
사용자가 직접 테스트한 뒤**: 버그가 나오면 재현 우선 원칙으로 고치고, 승인이 나면 이 섹션과 `04`에
"사용자 승인 완료(날짜)"를 추가하고 §0·§4의 "승인 대기 중" 문구를 지운다. 승인 전까지는 Phase 3
착수를 사용자에게 먼저 묻지 않는다.

## 3. 로컬에서 확인하는 법

**Expo 개발 서버 — 반드시 사용자 본인 터미널에서 실행한다.** 이 세션(Claude Code Bash 도구)엔
TTY가 없어 `npx expo start`를 아무리 `--tunnel`/`--non-interactive`로 돌려도 QR·`exp://` 접속
URL이 안 찍힌다(실측으로 확인 — Expo CLI가 `stdout.isTTY`를 보고 인터랙티브 UI를 켠다). 실기기
테스트가 필요하면 **"터미널에서 `npx expo start --tunnel ngrok` 직접 실행해 달라"고 사용자에게
요청**한다. 이쪽에서 먼저 띄웠다가 포트(8081)를 점유한 채로 끝내지 않도록 `taskkill`로 정리하고
넘긴다.

**버그 재현 루프(이번 세션에서 실제로 쓴 방식)**: 사용자가 실기기 스크린샷+증상을 캡처해 전달 →
관련 코드를 직접 읽어 원인 특정(추측 금지, 재현 우선 원칙) → 수정 → `tsc`/`jest`/`eslint` 전체
재검증 → 사용자가 Expo Go에서 리로드 후 재확인. 브라우저 자동화(claude-in-chrome)는 이번 하객
작업에선 쓰지 않았다 — 아래 §3-1(이전 세션의 브라우저 자동화 노하우)은 웹 프리뷰로 검증할 때만
참고한다.

### 3-1. (이전 세션 — 웹 프리뷰/브라우저 자동화로 검증할 때만 해당)
- **브라우저 자동화로 검증할 때(claude-in-chrome)**:
  - 스크린샷(`computer screenshot`)과 DOM `.click()`이 **세션 중 간헐적으로 타임아웃/무반응**할 수 있다
    (CDP 연결 플레이크니스로 추정). 증상이 나오면 **새 탭을 새로 만들어(`tabs_create_mcp`) 재시도**.
  - RN Web의 `Pressable`은 DOM 요소의 `.click()`으로 안 눌리는 경우가 있다 — `computer` 툴의 실제
    좌표 클릭을 우선 쓰고, 막히면 `PointerEvent`/`MouseEvent`를 직접 dispatch하는 JS 헬퍼가 안정적.
  - **OS/브라우저 네이티브 팝업**은 CDP로 전혀 못 본다 — `CalendarPicker`를 커스텀 RN 모달로 만든
    이유.
  - Reanimated rAF 애니메이션은 스크린샷 타임아웃을 유발할 수 있다 — 로직/좌표는 DOM 실측으로
    먼저 검증.
- **Supabase RPC/격리 재검증**: 프로젝트 루트에서 `@supabase/supabase-js`로 `.env` 키를 읽어 RPC를
  직접 호출하는 1회용 Node 스크립트(`node --env-file=.env 스크립트.mjs`, Node 20+). **검증 끝나면
  스크립트와 테스트 데이터 삭제**.
- **브라우저의 `localStorage.wedding.shareCode`가 이전 세션의 낡은/무효 코드로 남아있을 수 있다**:
  PT401(무효)이면 CRUD가 에러 없이 조용히 실패한다(단, 이제 네 feature는 `Alert`가 뜬다 — 이 문제는
  더 쉽게 드러난다). `javascript_tool`로 `localStorage.getItem('wedding.shareCode')` 확인 후 유효한
  코드로 교체.
- **낙관적 반영 실패 롤백은 `window.fetch`를 임시로 패치해 유도할 수 있다**: 특정 RPC 엔드포인트
  URL만 `Promise.reject`하도록 감싸면 해당 mutation만 실패시켜 롤백을 실측할 수 있다. **테스트 후
  반드시 복원**.
- **`expo-image-picker` 웹 구현의 파일 선택을 브라우저 자동화로 재현하는 법**(갤러리 테스트에서
  실측): 이 라이브러리는 `<input type=file>`을 만들어 `click()`이 아니라
  `dispatchEvent(new MouseEvent('click'))`으로 열기 때문에 일반 `file_upload` 도구(이미 DOM에 있는
  input을 대상으로 함)가 못 쓴다 — input이 클릭 시점에만 잠깐 존재했다 사라져 타이밍도 안 맞는다.
  `document.body.appendChild`를 가로채 `input[type=file]`이 추가되는 순간 그 input에 `click`
  캡처 리스너를 달아두고, 리스너 안에서 `DataTransfer`로 가짜 `File`을 만들어 `input.files`에
  주입한 뒤 `change` 이벤트를 수동으로 `dispatchEvent`하면 라이브러리의 `change` 리스너(이미 등록
  돼 있음)가 정상 동작한다. 이 경로는 실제 OS 네이티브 다이얼로그를 안 타므로 권한 팝업·파일 선택
  UX 자체는 검증 못 한다 — `docs/02-architecture.md` 갤러리 서브섹션에도 기록.

**디자인 목업**(`design/*.html`, 참조용): `file://`가 막히니 로컬 정적 서버 필요.
